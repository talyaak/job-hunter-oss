# 5. Gap bridging

```
For each missing or partial requirement: <list>.

1. State the employer's underlying need (what the technology is for).
2. Table: my real experience | related concept | strength of the link (strong / adjacent / none).
3. Give a truthful phrasing I could use, and an "unsupported claim to avoid" list with reasons.
4. If the gap is learnable, propose one small real project I could build and document, instead of wording tricks.
5. For years-of-experience gaps: state exact tenure, emphasise ownership and scope, and never stretch or reclassify
   unrelated experience.
6. For an industry label (e.g. one domain only): keep the real title/domain, lead with the engineering problem solved,
   and add one factual descriptor line under the employer.
```
